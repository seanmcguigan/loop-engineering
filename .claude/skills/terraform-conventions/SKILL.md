# Skill: terraform-conventions

Apply these rules whenever reading, writing, or reviewing any Terraform in this repo.

## Tagging Schema
Every resource must carry the following tags. Missing tags are a checkov violation.

| Tag Key       | Required | Example Value         |
|---------------|----------|-----------------------|
| `env`         | Yes      | `prod`, `staging`, `dev` |
| `team`        | Yes      | `platform`, `data`    |
| `service`     | Yes      | `ingress`, `postgres` |
| `cost-centre` | Yes      | `CC-1042`             |
| `ticket`      | Yes      | `PLAT-1234`           |
| `managed-by`  | Yes      | `terraform`           |

Enforce via a `locals` block that merges `var.common_tags` with resource-level tags, then pass `local.tags` to every resource.

## Directory Layout
All Terraform code lives under `terraform/` at the repo root:

```
terraform/
  modules/
    <module-name>/
      main.tf
      variables.tf
      outputs.tf
      versions.tf      # required_providers + required_version
      README.md        # auto-generated by terraform-docs
  environments/
    prod/
      main.tf          # module calls + local.common_tags
      backend.tf       # S3 backend config
      providers.tf     # provider versions + default_tags
      variables.tf
      terraform.tfvars
    staging/
    dev/
```

Modules must not contain `data` sources that reach outside their own state — pass external IDs in as variables.

## State Backend Rules
- Backend: S3 with native state locking — never local state.
  - Terraform 1.10+: set `use_lockfile = true` in the S3 backend block; no DynamoDB table required.
  - Legacy (pre-1.10): `dynamodb_table` for locking — still supported but no longer the recommended path.
- Bucket: `platform-tfstate-<account-id>-<region>`.
- Key pattern: `<env>/<service>/terraform.tfstate`.
- Encryption: `encrypt = true`, KMS key required.
- State must never be committed to the repo.

## Mandatory Policy Checks
Before any `terraform apply` to `env=prod`, run from the repo root:
1. `checkov -d terraform/environments/prod/ --compact --quiet` must exit 0.
2. `opa eval -d policies/ -i plan.json "data.platform.deny"` must return an empty set.
3. The sentinel file `.checkov-passed` must exist in the repo root (written by the CI step).

OPA path is always `policies/` relative to the repo root — not relative to the module or environment directory.

Checkov skip annotations (`# checkov:skip=...`) require an inline justification comment and a ticket reference.

## Version Pinning
- Provider versions: `~>` minor, never `>= x.0`.
- Terraform CLI: pin in `versions.tf` with `required_version = "~> 1.10"` (minimum for native S3 locking).
