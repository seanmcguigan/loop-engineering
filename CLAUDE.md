# platform-loops — Project Rules

## Purpose
This repo manages platform infrastructure loops: Terraform, Flux, and Kubernetes governance for all clusters.

## Bash Commands
```bash
# Validate Terraform before planning (run from an environment directory)
cd terraform/environments/prod && terraform validate && terraform fmt -check -recursive

# Run checkov policy checks against a Terraform environment
checkov -d terraform/environments/prod/ --compact --quiet

# Run OPA against a plan JSON (from repo root)
opa eval -d policies/ -i plan.json "data.platform.deny"

# Flux reconcile (dry-run)
flux reconcile kustomization infra --dry-run

# Diff kustomize output (requires clusters/ to be populated)
kubectl kustomize clusters/prod/ | kubectl diff -f -
```

## Non-Obvious Conventions
- All prod changes require a ticket reference in the commit message (format: `[PLAT-1234]`).
- Never commit secrets; secret-scan-pre-commit.sh runs on every pre-commit.
- Kustomize overlays live under `clusters/<env>/`, base manifests under `clusters/base/` — see `clusters/` directory (FluxCD manifests live there, Terraform code lives under `terraform/`).
- Terraform state backend is always remote (see `terraform-conventions` skill for details).
- Helm chart versions are pinned — no `latest` tags anywhere.
- Every new service addition must pass the `sre-verifier` agent check before merging.
- Module READMEs are auto-generated by `terraform-docs` — run it after changing variables or outputs.

## Running Loops
```bash
# Morning triage (read-only: CI failures, open issues, Flux status → state/ and triage/)
bash loops/morning-triage.sh

# PR policy check (terraform plan + checkov + OPA + PR comment)
PR_NUMBER=<n> bash loops/pr-policy-check.sh

# Nightly drift detection (EKS, Aurora, WAF → state/ and triage/ if drift found)
bash loops/drift-detection.sh
```

Each loop script runs `claude -p` with a scoped `--allowedTools` list — never expand that list without deliberate review.

## Directory Map
- `terraform/` — all Terraform code
  - `terraform/modules/` — reusable modules (vpc, eks, rds, iam-role, karpenter)
  - `terraform/environments/` — root modules per environment (prod, staging, dev)
- `clusters/` — FluxCD Kustomizations and HelmReleases per cluster (prod, staging, dev)
- `policies/` — OPA Rego policies for Terraform plan validation
- `loops/` — scheduled and CI-triggered loop entry points (the "heartbeat")
- `state/` — durable run output: triage findings, policy check logs, drift reports; persists across runs
- `triage/` — inbox for unresolved items surfaced by automations; review before each loop reruns
- `.claude/skills/` — domain rule sets loaded on demand
- `.claude/agents/` — subagent definitions for maker/checker verification
- `.claude/hooks/` — deterministic enforcement gates (not advisory)
- `.github/workflows/` — CI workflows that invoke loop scripts
- `docs/` — governance and observability standards (reference, not rules — rules live in skills)

## Domain Rules Live in Skills
Full conventions for each domain are defined in `.claude/skills/` and should be loaded by the relevant agent or slash command:
- `terraform-conventions` — tagging schema, module layout, state backend, checkov/OPA
- `k8s-governance` — labels, PodDisruptionBudget, NetworkPolicy, Istio mTLS
- `flux-conventions` — Kustomization structure, promotion flow, health checks
- `observability-standards` — New Relic APM, SLO dashboards, alert routing
- `cost-governance` — instance constraints, Karpenter NodePool rules
- `incident-runbook` — incident response steps
